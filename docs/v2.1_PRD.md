# GLOSTAT v2.1 — PRD

> **Status:** DRAFT 2026-05-13. Authoritative once approved by the project
> owner. Children of `ROADMAP_v2.md`.
>
> **One-line:** Ship two low-cost measurable signals + introduce
> `ThesisRegistry` so future thesis growth is a one-file change.

## Why v2.1

- Two new signals with measured AUC ≥ 0.55 in published research can land
  in a single sprint using already-wired data (yfinance, krx_short_client).
- The current per-thesis cost is ~4-place mechanical edit
  (`thesis_wrappers.py`, `_PHASE_SOURCES`, `synthetic_calibration_for_mock`,
  CLI wiring); v2.1's `@thesis` decorator collapses that to one decorated
  function.
- openkrx MCP has been connected for two sessions; v2.1 wraps it as a
  direct httpx client per the `ecos_client.py` / `dart_client.py` pattern.
- `load_calibration` is called per-`predict()` and re-reads up to 17 JSON
  files each time; a 1-line cache decorator yields 50–200x hindcast
  speedup.

## Out of scope

- v2.1 does NOT introduce the measurement gate (that is v2.2).
- v2.1 does NOT add earnings-domain signals (v2.3).
- v2.1 does NOT touch the gating composer or anti-herd machinery.
- v2.1 does NOT change Prediction output shape (still probability + CI;
  multi-horizon is v3.0).

## Deliverables

### 1. `experts/e_52w_high_proximity.py` (~120 LOC)

**Predicts:** 30d forward return direction.

**Signal rule:** Long if `close / max(close, 252d) ≥ 0.95`; short if
`close / max(close, 252d) ≤ 0.75`; neutral otherwise. Two-tier z-score
output, not a single threshold.

**Universe:** US (S&P 500 Top 50) + KR (KOSPI 200) + global ADRs available
through yfinance.

**Calibration target:** AUC 0.54–0.57 on n ≥ 500 per universe.

**Reference:** George & Hwang (2004, *Journal of Finance*) — winner-loser
spread 0.45%/month (t=4.5), AUC ≈ 0.55, robust 1963–2001 + international
replication.

**Data:** yfinance only (already wired; no new keys).

**Dependencies:** v2.1 #6 (`load_calibration` cache); v2.1 #4
(`ThesisRegistry`) — registers as
`@thesis(name="E_52W_HIGH_PROXIMITY", universe="any", horizon="swing_30d")`.

### 2. `experts/e_kr_short_interest.py` (~140 LOC)

**Predicts:** 30d forward return; high short-interest underperforms.

**Signal rule:** Top-decile KOSPI short-balance ratio → short (rank-based
within KOSPI 200 universe). Magnify around month-end mandatory short-cover
dates (KRX 결제일).

**Universe:** KOSPI + KOSDAQ where shortable.

**Calibration target:** AUC 0.55–0.58 on n ≥ 500 KR megacap.

**Reference:** Asquith, Pathak, Ritter (2005, *JFE*) — high-SI decile
underperforms 215 bps/month (t=3.6). Wang & Yu (2024, *Pacific-Basin
Finance Journal*) KR replication: monthly AUC 0.56 on KRX 2010–2022.

**Data:** `data/krx_short_client.py` (already wired in v1.4 N2). No new
API.

**Note:** The existing `EShortSellingKrExpert` from v1.4 N2 detects squeeze
candidates (different signal). v2.1 #2 is the anomaly-predictor variant
and lives in a separate file. Both can coexist in the calibration table.

### 3. `data/openkrx_client.py` (~180 LOC)

**Wraps:** `mcp__openkrx__get_kospi_stock_daily` and
`mcp__openkrx__get_kospi_index_daily` as direct httpx calls against
`https://data-dbg.krx.co.kr/svc/apis/sto/...`.

**Auth:** `GLOSTAT_KRX_API_KEY` env var; graceful skip if absent (mirrors
ECOS/DART pattern per INV-GS-107/108).

**Rate:** 10 req/sec self-throttle.

**Snapshot Broker:** integrated per INV-GS-022; respects the new two-level
storage from v2.1 #5 (raw shard + materialized tile).

**Endpoints covered in v2.1:**
- `stk_bydd_trd` — daily OHLCV cross-section (KOSPI ~948 rows, KOSDAQ ~1500)
- `idx_bydd_trd` — daily index cross-section

**Out of scope for v2.1:** futures/options/ETF/ETN/ELW endpoints (those
land in v2.4 if there is a thesis that needs them).

**New invariant:** `INV-GS-115` — openkrx ToS quarterly re-check (mirrors
INV-GS-035 for RavenPack); graceful skip if `GLOSTAT_KRX_API_KEY` unset.

### 4. `predictor/registry.py` (~200 LOC)

The single biggest brittleness reduction in v2.1.

```python
from glostat.predictor.registry import thesis, ThesisRegistry

@thesis(
    name="E_52W_HIGH_PROXIMITY",
    universe="any",
    horizon="swing_30d",
    calibration_source="docs/CALIBRATION.md#e_52w_high_proximity",
)
async def score_52w_high(ctx: ThesisContext) -> SignalContribution:
    ...
```

`ThesisRegistry.all()` enumerates every registered thesis;
`predictor/composite.collect_contributions()` becomes:

```python
async def collect_contributions(ticker, ts, cal_table):
    return [
        await fn(ThesisContext(ticker=ticker, ts=ts, cal=cal_table.get(name)))
        for name, fn in ThesisRegistry.all()
    ]
```

Removes the 16-arg switch in `predictor/thesis_wrappers.py` and the
universe-check duplication across 10 wrappers (architect B1, B3).

**Migration:** existing thesis modules add the decorator and remove their
wrapper entry. Backward compat: the wrapper file can `import *` from the
new module structure for one minor release, then deletion lands in v2.3.

**New invariant:** `INV-GS-116` — new thesis modules MUST self-register via
`@thesis`; raw wrapper-table edits are PR-blocked.

### 5. `snapshot_broker.py` two-level storage (~140 LOC)

Keep `shards/{leaf_hash[:2]}/{leaf_hash}.parquet` as the audit artifact
(unchanged — Merkle root identity preserved). Add a second materialization
write:

```
tiles/{edge_type}/date={YYYYMMDD}/data.parquet
```

Schema is column-typed per edge_type (defined in
`data/tile_schemas.py`). For `openkrx_daily`: `(isin, ticker, date, close,
volume, mktcap, ...)`.

SQLite `snapshots` table gains a nullable `tile_path` column pointing to
the tile. Cross-section read paths consult tiles first, fall back to raw
shard deserialization if `tile_path IS NULL`.

**Migration:** existing shards remain valid. Tiles are written for new
saves only. A background migration script (`scripts/migrate_tiles.py`)
can backfill from existing shards if desired but is not required for
correctness.

**New invariant:** `INV-GS-117` — every cross-section `save_snapshot` MUST
write both raw shard AND tile within the same SQLite transaction.

### 6. `@lru_cache` on `load_calibration` (~20 LOC)

```python
@functools.lru_cache(maxsize=8)
def load_calibration(cache_dir: Path = DEFAULT_CACHE_DIR) -> CalibrationTable:
    ...
```

Plus: thread the cached table through hindcast call sites in
`replay/phase_kr.py` and `replay/validation_harness.py` explicitly via the
existing `cal_table` parameter on `predict()`.

**Cache invalidation:** the cache key is `cache_dir`; when calibration is
rewritten (quarterly per INV-GS-105), the writer must call
`load_calibration.cache_clear()` after `save_calibration_table`.

## Success criteria

1. `pytest -q` passes (regression-free).
2. `pytest -q tests/test_e_52w_high_proximity.py tests/test_e_kr_short_interest.py` passes; coverage ≥ 80%.
3. `pytest -m calibration tests/test_phase_kr_v21.py` shows:
   - `E_52W_HIGH_PROXIMITY` AUC ≥ 0.53 on KR + US universes (lower bound of literature range).
   - `E_KR_SHORT_INTEREST` AUC ≥ 0.54 on KOSPI 200.
   - Both reach n ≥ 500 in their respective hindcast windows.
4. Hindcast over 200 KOSPI tickers × 365 days × 17 theses runs in < 60 seconds wall-clock on a 2026 macOS dev machine (50–200x improvement over current ~30 min via `load_calibration` cache + `predict()` cal_table threading).
5. Adding a 18th thesis (sandbox `E_DEMO`) requires touching only one new file (the expert module with `@thesis` decorator) — no edits to `thesis_wrappers.py`, `calibration.py`, `composite.py`, or `cli.py`.

## Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| AUC for new signals falls below literature range due to post-2010 alpha decay | Medium | Pre-register expected range in test; if below, ship as weight=0 with public note in `docs/CALIBRATION.md`. |
| `ThesisRegistry` import-order issue (decorators register at import time) breaks lazy loading | Low-Medium | Add explicit `import glostat.experts.all  # registers everything` to `predictor/__init__.py`; document. |
| Two-level storage doubles disk usage for openkrx-heavy hindcast runs | Medium | Tiles compress well (Snappy); estimate ~1.2x raw size. Add `glostat snapshot prune --keep tiles` for users who want tile-only retention. |
| `@lru_cache` on `load_calibration` masks calibration table updates in long-running CLI sessions | Medium | The cache must be cleared by the recalibration writer; add an integration test that calls write then `predict()` and asserts the new value is read. |

## Sequencing within v2.1

Recommended PR order:

1. **PR1** — `@lru_cache` on `load_calibration` + hindcast threading (#6). Smallest, biggest perf win.
2. **PR2** — `ThesisRegistry` (#4). Foundation for everything else.
3. **PR3** — Migrate existing 17 theses to `@thesis` decorator. No new behaviour.
4. **PR4** — `data/openkrx_client.py` + two-level storage (#3 + #5). Adds infrastructure but no thesis.
5. **PR5** — `experts/e_52w_high_proximity.py` (#1) + tests + calibration.
6. **PR6** — `experts/e_kr_short_interest.py` (#2) + tests + calibration.

Each PR independently shippable to a `v2.1-staging` branch; v2.1 release
cut when all 6 land + Phase KR hindcast confirms AUC ranges.
